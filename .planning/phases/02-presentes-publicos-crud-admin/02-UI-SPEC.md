## Spacing Scale

Declared values (multiples of 4 only). All spacing expressed as Bootstrap utility classes mapped to the scale below.

| Token | Value | Bootstrap Equivalent | Usage |
|-------|-------|---------------------|-------|
| xs | 4px | `gap-1`, `p-1` | Icon gaps, inline badge padding |
| sm | 8px | `gap-2`, `p-2` | Compact element spacing, card action gap |
| md | 16px | `gap-3`, `p-3` | Default element spacing, card body padding |
| lg | 24px | `gap-4`, `p-4` | Section padding, form group spacing |
| xl | 32px | `gap-5`, `py-5` equivalent | Layout column gaps |
| 2xl | 48px | `py-5` (Bootstrap = 48px at default) | Page section breaks |
| 3xl | 64px | custom `padding: 4rem` in app.css | Hero-level page-top padding |

Exceptions:
- Touch targets for action buttons: minimum 44px height (`min-height: 44px` enforced on `.btn` in app.css for mobile)
- Card image height: fixed 200px on desktop, 160px on mobile (not an 8-point value — visual constraint)

## Typography

Bootstrap 5 base font size is 16px (1rem). All sizes below map to Bootstrap utility classes or inline rem values.

| Role | Size | Weight | Line Height | Bootstrap Class / CSS |
|------|------|--------|-------------|----------------------|
| Body | 16px (1rem) | 400 (regular) | 1.5 | default — no class needed |
| Label / small detail | 14px (0.875rem) | 400 (regular) | 1.4 | `.small` or `.fs-6` |
| Subheading / card title | 20px (1.25rem) | 600 (semibold) | 1.3 | `.fs-5 .fw-semibold` |
| Heading / page title | 28px (1.75rem) | 600 (semibold) | 1.2 | `.fs-3 .fw-semibold` |

Rules:
- Only two weights used: 400 (regular) and 600 (semibold). Semibold (600) is used for all emphasis including destructive/alert copy — no 700 bold.
- No italic anywhere in this phase.
- Card gift name: 20px / 600 / lh 1.3
- Card price: 16px / 600 / lh 1.5 — rendered in accent color
- Badge text: 14px / 400 — uppercase only for "ESGOTADO" badge

## Color

Bootstrap 5 default palette used. Custom tokens defined in `public/assets/css/app.css`.

| Role | Value | Bootstrap Token | Usage |
|------|-------|----------------|-------|
| Dominant (60%) | `#ffffff` / `#f8f9fa` | `bg-white` / `bg-light` | Page background, card surfaces, modal body |
| Secondary (30%) | `#e9ecef` | `bg-light`, `border-light` | Admin sidebar (`bg-light`), nav bar background, table zebra rows |
| Accent (10%) | `#0d6efd` | Bootstrap `primary` | Primary CTAs only — see reserved list below |
| Destructive | `#dc3545` | Bootstrap `danger` | Delete button, error alerts, "ESGOTADO" badge background |
| Featured highlight | `#ffc107` | Bootstrap `warning` | Featured badge/ribbon only — no other use |

**Accent (`#0d6efd`) reserved for:**
1. "Escolher este presente" button (public gift card — available state only)
2. "Criar conta" / "Entrar" submit buttons inside the auth modal
3. Admin "Salvar" (create/edit gift form) primary action button
4. Active nav-link indicator in admin sidebar

**Sold-out state color contract:**
- Card: `opacity: 0.55` + `filter: grayscale(30%)` applied via `.gift-card--esgotado` CSS class
- Button: `btn-secondary` (Bootstrap gray, `#6c757d`) + `disabled` attribute — no blue accent
- Badge: `badge bg-danger text-white` with text "ESGOTADO" — uppercase, 14px

**Featured state color contract:**
- Badge: `badge bg-warning text-dark` positioned `position: absolute; top: 8px; right: 8px` — text "DESTAQUE"
- No ribbon or diagonal stripe — label badge only (avoids visual noise with Bootstrap 5)
- Featured cards are NOT re-ordered visually in the grid by CSS — ordering is controlled by the sort JS/PHP logic (D-09)

## Component Inventory

### Public gifts page (`/gifts`)

**Gift card** — Bootstrap `.card` with the following structure:
```
.card.gift-card.h-100.shadow-sm
  .card-img-top (200px height, object-fit: cover; placeholder if no image)
  .position-relative (wraps image — featured badge absolutely positioned here)
  .card-body.d-flex.flex-column
    .card-title.fs-5.fw-semibold  ← gift name
    .card-text.small.text-muted   ← short description (2 lines max, overflow: hidden)
    .badge.bg-secondary.mb-2      ← category (if present)
    .fw-semibold.text-primary     ← "R$ {price}" (if present)
    .small.text-muted             ← "Disponível: {N}" (if qty visible)
  .card-footer.bg-transparent.border-0.pb-3
    button.btn.btn-primary.w-100  ← "Escolher este presente" (available state)
    button.btn.btn-secondary.w-100[disabled] ← (sold-out state)
```

**Grid layout:**
- Desktop (≥992px): `row-cols-lg-3`
- Tablet (≥768px): `row-cols-md-2`
- Mobile (<768px): `row-cols-1`
- Column gap: `g-4` (Bootstrap gutter = 24px / lg token)

**Filter bar** — rendered above the grid:
```
.row.g-3.mb-4.align-items-end
  .col-md-5: input[type=text]#search-input.form-control  ← search by name
  .col-md-4: select#category-filter.form-select          ← filter by category
  .col-md-3: select#sort-filter.form-select              ← sort order
```
- Search fires on `input` event with 300ms debounce
- Category and sort fire on `change` event immediately
- All three controls trigger a single `fetch('/gifts/filter?...')` call
- Response: PHP returns rendered HTML of `.row.g-4` card list — JS replaces `#gifts-container` innerHTML
- Loading state: `#gifts-container` gets `opacity: 0.5` + `pointer-events: none` while fetch is in flight

**Empty state** (zero results from filter): injected by PHP inside `#gifts-container`:
```html
<div class="col-12 text-center py-5 text-muted">
  <i class="bi bi-gift fs-1 d-block mb-3"></i>
  <p class="fs-5 fw-semibold">Nenhum presente encontrado</p>
  <p class="small">Tente ajustar os filtros ou a busca.</p>
</div>
```

### Guest authentication modal

Bootstrap `.modal` with `id="authModal"` and `data-bs-backdrop="static"` (cannot dismiss by clicking outside — user must complete or explicitly close).

Structure:
```
.modal.fade#authModal
  .modal-dialog.modal-dialog-centered
    .modal-content
      .modal-header
        h5.modal-title  ← "Identificação"
        button.btn-close[data-bs-dismiss="modal"]
      .modal-body
        ul.nav.nav-tabs.mb-4
          li: a.nav-link.active[data-tab="signup"]  "Criar conta"
          li: a.nav-link[data-tab="login"]          "Entrar"
        div#tab-signup (active by default)
          form#form-signup
            .mb-3: label + input[name=name].form-control        ← Nome completo
            .mb-3: label + input[name=email].form-control       ← E-mail
            .mb-3: label + input[name=phone].form-control       ← Telefone (opcional)
            .mb-3: label + input[name=password].form-control    ← Senha
            div#signup-error.alert.alert-danger.d-none          ← inline error
            button.btn.btn-primary.w-100[type=submit]  "Criar conta"
        div#tab-login.d-none
          form#form-login
            .mb-3: label + input[name=email].form-control       ← E-mail
            .mb-3: label + input[name=password].form-control    ← Senha
            div#login-error.alert.alert-danger.d-none           ← inline error
            button.btn.btn-primary.w-100[type=submit]  "Entrar"
        div#auth-success.alert.alert-success.d-none  ← success message before modal closes
      .modal-footer.d-none  ← no footer
```

Tab switching: vanilla JS toggles `d-none` on `#tab-signup` / `#tab-login` and `active` class on nav links. No page navigation.

Form submission: via `fetch()` to `/auth/guest-signup` or `/auth/guest-login`. JSON response `{success: true}` or `{error: "message"}`. On error: show inline `.alert-danger` with `error` text. On success: show `#auth-success` ("Conta criada! Continuando..."), then close modal after 1200ms via `bootstrap.Modal.getInstance('#authModal').hide()`.

Gift ID preservation: JS sets `window._pendingGiftId = giftId` when "Escolher este presente" is clicked. This value persists through modal open/close for Phase 3 to consume.

CSRF: both forms include a hidden `csrf_token` input. Token written into the HTML by PHP at page render time into `data-csrf-token` attribute on `#authModal`. JS reads it and injects into fetch body.

### Admin gifts table (`/admin/gifts`)

Extends existing `admin.php` layout. Main content area:

**Filter bar:**
```
.d-flex.justify-content-between.align-items-center.mb-4
  h1.fs-3.fw-semibold  "Presentes"
  a.btn.btn-primary[href="/admin/gifts/create"]  "+ Novo presente"
.row.g-3.mb-4
  .col-md-6: input[type=text]#admin-search.form-control  ← busca por nome (GET param, page reload)
  .col-md-3: select#admin-status-filter.form-select      ← todos / ativos / inativos
  .col-md-3: button.btn.btn-outline-secondary  "Filtrar"
```

Note: admin filter uses standard GET form submit (full page reload) — no fetch required per D-22 (no dynamic requirement stated for admin).

**Table:**
```
.table-responsive
  table.table.table-hover.align-middle
    thead.table-light
      tr: th(thumb) th(Nome) th(Categoria) th(Preço) th(Disponível) th(Status) th(Ações)
    tbody
      tr (one per gift)
        td: img.rounded[width=48 height=48 style="object-fit:cover"]  ← thumb
        td: span.fw-semibold  ← gift name
        td: span.text-muted.small  ← category or "—"
        td: span  ← "R$ {price}" or "—"
        td: span  ← "{available_qty} / {total_qty}"
        td: span.badge  ← status badge (see below)
        td.text-nowrap
          a.btn.btn-sm.btn-outline-primary[href="/admin/gifts/{id}/edit"]  "Editar"
          button.btn.btn-sm.btn-outline-secondary.ms-1  "Inativar" or "Ativar" (inline toggle via POST)
          button.btn.btn-sm.btn-outline-danger.ms-1  "Excluir"
```

Status badge values:
- Active: `badge bg-success` "Ativo"
- Inactive: `badge bg-secondary` "Inativo"

**Delete confirmation:** `window.confirm('Excluir este presente permanentemente? Esta ação não pode ser desfeita.')` — standard browser confirm. If confirmed, submits a hidden POST form with `csrf_token` to `/admin/gifts/{id}/delete`. No custom modal for delete confirmation.

**Inativar/Ativar toggle:** inline POST form (no JS fetch) — button submits to `/admin/gifts/{id}/toggle-active` with `csrf_token`. Page reloads to show updated status.

### Admin gift create/edit form (`/admin/gifts/create`, `/admin/gifts/{id}/edit`)

Single form `form[method=POST][enctype=multipart/form-data]` inside the admin layout.

Field layout — two-column on desktop, single column on mobile:
```
.row.g-4
  .col-md-8  ← main fields
    Nome *: input[name=name].form-control  (triggers JS slug generation on input event)
    Slug *: input[name=slug].form-control  (editable, pre-filled by JS from name)
    Descrição: textarea[name=description].form-control[rows=4]
    Categoria: input[name=category].form-control  (free text)
    Preço sugerido: input[name=price][type=number][step=0.01].form-control
    Tipo: select[name=type].form-select  ← "Individual (single)" / "Múltiplos (multi)"
    Quantidade total: input[name=total_qty][type=number].form-control
    Quantidade disponível: input[name=available_qty][type=number].form-control
  .col-md-4  ← sidebar fields
    Imagem: input[name=image][type=file][accept=".jpg,.jpeg,.png,.webp"].form-control
    .mt-2: img#image-preview.img-fluid.rounded[style="display:none;max-height:200px"]
    .form-check.mt-3: input[name=featured][type=checkbox]#featured + label  "Destacado"
    .form-check.mt-2: input[name=active][type=checkbox]#active[checked] + label  "Ativo"
.mt-4
  button.btn.btn-primary[type=submit]  "Salvar presente"
  a.btn.btn-outline-secondary.ms-2[href="/admin/gifts"]  "Cancelar"
```

Image preview: JS `input[type=file]` `change` listener reads `FileReader.readAsDataURL()`, sets `#image-preview` src and removes `d-none`. Existing image shown on edit form by default.

Slug generation: JS listens to `input` on `[name=name]`, converts to lowercase, replaces spaces with `-`, removes non-alphanumeric-hyphen chars, writes to `[name=slug]` only when slug field has not been manually edited (track with a `data-auto` attribute).

Validation errors: PHP sets flash errors OR re-renders form with `.is-invalid` class on each invalid field and `.invalid-feedback` div below it.

## Interaction States

### Gift card states

| State | Visual Change | Button |
|-------|--------------|--------|
| Available (default) | Full opacity, no overlay | `btn-primary` "Escolher este presente" |
| Sold-out | `.gift-card--esgotado`: `opacity: 0.55; filter: grayscale(30%)` on entire card | `btn-secondary disabled` "Indisponível" |
| Featured | Badge `"DESTAQUE"` `bg-warning text-dark` top-right of card image | Same as available |
| Featured + sold-out | Both overlays apply | `btn-secondary disabled` "Indisponível" |

Custom CSS in `public/assets/css/app.css`:
```css
.gift-card--esgotado {
  opacity: 0.55;
  filter: grayscale(30%);
}
.gift-card__featured-badge {
  position: absolute;
  top: 8px;
  right: 8px;

.gift-card .card-img-top {
  height: 200px;
  object-fit: cover;
}
@media (max-width: 767.98px) {
  .gift-card .card-img-top {
    height: 160px;
  }
```

### Image placeholder (no image uploaded)

Render a `div.gift-card__placeholder` with a Bootstrap Icon `bi-image` (font-size 2rem) in place of `img.card-img-top`. No broken image icon, no empty space.

### Filter loading state

```javascript
// While fetch is in flight:
container.style.opacity = '0.5';
container.style.pointerEvents = 'none';
// On response:
container.style.opacity = '1';
container.style.pointerEvents = '';
container.innerHTML = responseHtml;
```

## Accessibility

- All `img` elements must have `alt` attribute: gift name for gift images, empty string for decorative
- All form inputs must have associated `label` (not placeholder-only)
- Disabled button state uses both `disabled` HTML attribute and Bootstrap `.disabled` class
- Auth modal must trap focus while open (Bootstrap 5 handles this natively)
- Color is not the sole indicator of state — text labels ("ESGOTADO", "DESTAQUE") accompany color badges
- Touch targets: minimum 44px height on all `.btn` elements on mobile (enforced via app.css)

## Implementation Notes for Executor

1. Bootstrap Icons CDN must be added to both `main.php` and `admin.php` `<head>`: `<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bootstrap-icons@1.11/font/bootstrap-icons.min.css">`
2. All custom CSS classes (`.gift-card--esgotado`, `.gift-card__featured-badge`, `.gift-card__placeholder`) go in `public/assets/css/app.css`
3. All vanilla JS for the gifts page (search debounce, fetch filter, modal tab switching, slug generation, image preview) goes in `public/assets/js/app.js` — modular functions, no global namespace pollution beyond one `GiftPage` object
4. The `/gifts/filter` endpoint returns rendered HTML partial (the card grid rows), not JSON — PHP server-side rendering per D-06
5. Auth endpoints (`/auth/guest-signup`, `/auth/guest-login`) return JSON `{success: true, redirect: null}` or `{error: "message"}` — not full page responses
6. CSRF token for modal forms: embed as `data-csrf-token` attribute on `#authModal` div, read by JS before each fetch
